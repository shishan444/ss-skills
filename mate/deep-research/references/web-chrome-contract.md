# 与 web-chrome 的协作契约

## 职责划分

`deep-research` 决定为什么研究、研究什么、证据是否够、如何综合。

`$web-chrome` 决定怎样安全访问网页，包括：

- 使用现有 Chrome 与登录态
- 标签页获取、标记、保活和关闭
- DOM 提取与 GUI 交互的选择
- 反爬、验证码、登录和网络拦截识别
- 站点经验复用与失败降级

不要在 `deep-research` 内启动另一套 Chrome、Playwright、远程调试端口或无头抓取服务。

## 每次在线研究的执行顺序

1. 完整读取 `$web-chrome` 的 `SKILL.md`。
2. 展示其要求的风险提示。
3. 运行依赖检查，确认 Chrome 调试接口和所需工具可用。
4. 获取现有标签页快照并记录初始 target IDs。
5. 查询适用的站点模式和既有经验。
6. 通过标签池申请或复用本任务标签页，使用明确的任务标签。
7. 导航后先做拦截检测，再提取正文。
8. 长时间运行时按 `$web-chrome` 要求刷新标签页租约。
9. 任务结束只关闭本任务创建或管理的标签页；保留用户原有标签页。

标签页数量受 `$web-chrome` 的全局软上限与硬上限约束。若接近上限，先整理标签页，再继续扩展来源。

## 访问方式选择

### 已知静态 URL

对于公开、静态、无需登录的已知 URL，遵循 `$web-chrome` 允许的轻量获取方式。结果仍需记录 URL、访问时间和提取方法。

### 动态、登录或交互页面

必须通过用户 Chrome 的 CDP 会话访问。优先 DOM 查询和页面求值；只有 DOM 无法完成时才使用 GUI 操作。

### 搜索结果

搜索页只用来发现候选链接。报告引用必须指向实际打开并核验过的落地页，而非搜索摘要。

## 证据提取最小集

一次有效页面提取至少产生：

- `title`
- `url`
- `publisher`
- `published_at`，若页面没有则为空并说明
- `retrieved_at`
- `access_status` 与必要时的 `failure_reason`
- `extraction_method`
- `locator`
- 一个或多个与研究问题关联的 `claims`

正文摘录只保存支持主张所需的短片段。除非用户明确要求归档，不默认保存整页 HTML。

## 拦截与降级

出现登录墙、验证码、频率限制、空壳页面或权限错误时：

1. 使用 `$web-chrome` 的检测脚本确认拦截类型。
2. 检查是否可通过用户已有登录态、GUI 操作或站点模式恢复。
3. 同一策略确认失败后停止重复尝试。
4. 记录 URL、时间、失败原因和尝试过的方式。
5. 改用同一主张的其他来源，或在证据账本中留下缺口。

不得把被拦截页面的搜索摘要当成已核验证据。

## 标签页安全

- 开始前保存 target 快照。
- 每个研究主题使用独立任务标签。
- 只关闭当前任务创建或明确接管的 target。
- 不关闭用户原有、未接管或无法确认归属的标签页。
- 避免在多个标签页并行触发同一站点的高频请求。

## 交付记录

在 `manifest.json` 中汇总：

- 浏览器提取成功与失败的页面数量
- 使用过的提取方式
- 被拦截的来源及替代来源
- 最终仍未解决的访问限制
