# 单份事例的适用性与验证设计

## 事例为何适合

这三轮围绕同一个 MetaSkill 体系依次发生：第 1 轮推翻“Meta 层属于编程流程”的旧范围，第 2 轮纠正“人类思维转清晰内容涵盖全部 MetaSkill”的过窄概括，第 3 轮在保留 MetaSkill 原子化、跨场景定位的前提下，转入其中一个具体 skill 的定义。第 2 轮没有明确撤回第 1 轮所说的“解决人和 AI 的沟通”这一上层目的，不应擅自判为失效。每轮都对前一轮的有效意图作出不同更新，足以观察模型是否把最新一句当作全部任务。

材料的限制是只保存用户输入和简短背景，没有助手回复，也没有证据证明中间没有其他轮次。因此验证结论限于这组三条历史记录形成的连续输入，不外推为完整历史对话表现。

## 可判定的预期

- 第 1 轮后：有效意图是重新界定跨场景、原子化的 MetaSkill；用户此时强调人机沟通与思维显化，但不能擅自把这些例子变成 MetaSkill 的全部范围。
- 第 2 轮后：保留跨场景、原子化定位；明确撤回“人类思维转清晰内容涵盖全部 MetaSkill”的解释。若仍把全部 MetaSkill 归为思维显化，则失败。
- 第 3 轮后：当前焦点转为定义 MetaSkill 中的 `intent-understanding`，包括调用时机、输入、结构化输出与“只做意图理解”的边界；上层体系的跨场景、原子化定位仍是背景。若继续把第 2 轮的范围纠偏当成当前任务，或把意图理解 skill 写成会追问、设计方案的能力，则失败。
- 三轮中，用户明说的内容与模型推断必须分开；不得把过时理解留下来与新理解并列，也不得把第 3 轮理解成已要求编写文件。

## 验证层级

- L1：检查 `SKILL.md` 是否明确规定保留、覆盖、退出和焦点转移的更新语义。
- L2：把唯一事例依次输入独立评审，检查每一轮得到的当前有效意图和变化说明。
- L3：当前交付是纯文本 skill，没有网页、应用入口或用户界面；不虚构浏览器操作。人工按三轮顺序阅读实际输出，判断能否直接发现遗漏或误读。

通过判定以实际输出为依据；静态文本检查只证明规则存在，不能代替连续对话的行为验证。

## 实际验证记录

- 历史引文核对：三轮用户输入均与原评测记录逐字一致。
- 结构检查：使用 Ruby YAML 解析验证 frontmatter、名称、描述、引用路径和占位文本，均通过。标准 `quick_validate.py` 因当前 Python 缺少 `yaml` 模块而未能启动，不能记为标准脚本通过。
- 独立行为演练：评审只读取新版 `SKILL.md` 和本事例，按顺序分别生成三轮输出；未读取本文件和旧评测预期。第 1 轮保留跨场景、原子化定位；第 2 轮明确排除“思维转清晰内容是全部 MetaSkill”；第 3 轮转向意图理解 skill 的调用时机、输入、结构化输出与只做理解的边界，且未把早先的追问例子强加给它。本事例判为通过。
- 人工复核：第三轮输出保留了仍有效的上层目的和范围，同时正确缩小当前焦点。输出中的“隐性要求”被标为依据上下文推得，没有冒充用户明说。

独立评审的第 3 轮输出摘录：“现在你把讨论焦点转到其中的『意图理解 skill』：用户输入信息时就调用它，结合当前 prompt 和相关上下文识别表达的意图，整理出需求、目标、显性要求、依据上下文推得的隐性要求，以及背后的目的，并作结构化输出。这个 skill 的职责止于意图理解。”

该次同主题验证只用了一份三轮事例，且缺少历史助手回复；尚未验证跨会话、上下文压缩或纠正助手既往误解时的表现。
